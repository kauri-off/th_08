`gh.sh` notes (hard-won):
- `-scriptPath` accepts ONE directory here; passing several options does not work. The dir must
  contain every .java you need (this session's copies of the shared tools plus local ones).
- `HOME=/tmp/opencode/ghome` is forced to isolate Ghidra config from the main session.
- If ANY .java in the script dir fails to compile, Ghidra silently reports "OSGi bundle … could not
  be found" for ALL scripts in that dir. Verify by compiling against the Ghidra jars; env `javac`
  (Java 17) produces class files Ghidra (needs 21+) cannot load, so compile errors are best found by
  bisecting the dir.
- Ghidra 12: `Instruction.getOpObjects(Class)` does not exist — iterate `getNumOperands()` /
  `getOpObjects(i)`.

## Trail (what was verified, and how)

1. **fmt parse** — 21 records × 0x34 + 17-byte zero trailer; no header/count; terminator = name[0]==0.
   Checks in `dump_fmt.py` all pass (contiguity, alignment, loop<length, preload≥length, last
   end == 449,961,024, single WAVEFORMATEX).
2. **Container** — `FUN_004477B1` reads 16 bytes and requires `ZWAV`, 1, 0x800; dword3 unused.
   Track 0 `start` == 0x10. `"thbgm.dat"` @0x4B67CC, alt `"th08.dat"` @0x4B66C4 selected by
   `DAT_018BDC7C` (== 0, no writer ⇒ dead branch).
3. **Loop semantics (the headline)** — `FUN_004733E0(obj, loopFlag)`:
   flag 0 (or loop_start<1): seek `start`, remaining = `length`;
   flag 1: seek `start + loop_start`, remaining = `length − loop_start`.
   Only loopFlag=1 call site: `0x472FB0` in `FUN_00472D30` (HandleWaveStreamNotification) on
   underrun. `FUN_00473300` (SetCurrentRecord) always starts with flag 0. ⇒ play `[0,length)` once,
   then loop `[loop_start,length)` forever; loop end == length; units bytes.
4. **Streaming** — 16×44100 B ring (4.0 s), DSBPOSITIONNOTIFY per buffer; write pos `(pos+len)%obj+8`;
   silence via wBitsPerSample (0x80/0). File mode = default (cfg flag bit13 clear); memory/preload
   mode mallocs `preload_bytes` per track from `start` (`FUN_0045CE70`), clamped to `length`.
5. **Track selection** — by name: `FUN_00447D56(slot, "bgm/th08_XX.mid")` rewrites ext to `.wav`,
   queues type 1; `FUN_00447F21` queues type 2 with index 0xFFFFFFFF (name lookup by
   `FUN_0045C6B0`, which returns 0 when not found); by index: `FUN_00447E47`.
6. **Stage mapping** — `.std` +0x290/+0x310/+0x390 names (consumer `FUN_0043ABD7`); table of
   verified values in `02_bgm.md` §5.2. music room No./titles from `work/musiccmt_utf8.txt`.
7. **fmt order discovery** — compiled tables `0x4C7240` (stage→[theme,boss,third], 9×12) and
   `0x4C7670` (18×20 + sentinel, keyed by `DAT_0164D0B8`, selection = first `key >= x`) use
   **music-room numbering** (14=15, 15=13b, 16=18, 17=19, 18=16, 19=17). The shipped fmt is
   lexicographic order, differing exactly at positions 14..19. By-name paths are unaffected;
   by-index paths (only fed by the baked tables) mismatch for those six tracks. `FUN_0046BBC0`
   sets `DAT_0164D0B4 |= 0x4001` while building a 15-per-row spell-card grid (⇒ bit 14 selects the
   baked-table path; spell-practice-like mode). `FUN_00439916`/`FUN_00439961` read table fields.
8. **`_s` stage files** — exe contains both `stageN.std` and `stageN_s.std` literals; the `_s` files'
   +0x290 names differ (stage1_s = `th08_02` — not a real track; several others `th08_13b` /
   `th08_13_b` — note the variant spelling). Unresolved; see `02_bgm.md` §7.
